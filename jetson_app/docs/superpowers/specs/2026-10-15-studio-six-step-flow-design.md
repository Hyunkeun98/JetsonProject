# jetson-studio 6단계 흐름: 전체 수집 후 태그 추천

작성일 2026-10-15 / 상태: 검토 대기 / 앞선 설계: `2026-10-14-studio-ui-design.md`(이 문서가 그 4단계 흐름을 대체한다)

## 1. 목적

지금 화면은 태그를 **먼저** 골라야 수집이 시작되고, 태그 추천은 이미 저장해 둔 데이터 폴더가 있어야만 된다. 처음 쓰는 사람은 어떤 태그가 점수에 맞는지 모른 채 막힌다.

바꾸려는 것: 브로커에서 들어오는 **전체 데이터를 먼저 원본 그대로 모으고**, 그 데이터로 태그를 추천받은 뒤, 고른 태그로 학습·감시한다.

성공 기준
- 저장해 둔 데이터가 없어도, 브로커 연결 정보만으로 수집 → 태그 추천 → 학습 → 감시까지 화면에서 끝낼 수 있다.
- 태그를 나중에 골라도 **다시 수집하지 않는다**(원본을 저장해 두므로).
- run3로 학습한 결과가 기존과 같다(σ: X 3.9e-5, Z 3.5e-6, CV 3.4e-5). run4에서 7/9 검출, 정상 알람 0건이 유지된다.

## 2. 결정 사항 (대화에서 합의됨)

| 항목 | 결정 |
|---|---|
| 흐름 | 1 연결 → 2 살펴보기 → 3 전체 수집 → 4 태그 추천 → 5 학습 → 6 감시 |
| 살펴보기(2) | 임시 구독만 한다. 아무것도 저장하지 않고 끝나면 구독을 끊는다 |
| 수집 종료(3) | 사용자가 "수집 종료"를 누른다. 상한(기본 1GB)에 닿으면 자동 종료하고 알린다 |
| 이상 구간 제외 | 없음. 섞였으면 "버리고 처음부터"만 제공 |
| 최소 수집량 | **10사이클**. 부족하면 학습 전에 "학습 데이터가 적다"고 **경고만** 한다(학습은 막지 않는다) |
| `min_samples` 입력칸 | 없앤다 |
| 폴더 불러오기 | 남긴다. 3~4단계에서 "이미 저장한 데이터 폴더 불러오기"로 수집본을 대신할 수 있다 |
| 앱 재시작 | 모델이 있으면 6단계, 수집본만 있으면 4단계, 연결 정보만 있으면 3단계 |
| 보관 | 장비마다 현재 수집본 하나. 새로 수집하면 이전 것은 `archive/`로 옮긴다 |
| 데이터 커밋 | 수집본은 `workspace/` 아래에 쌓이고 `.gitignore` 대상이다. 저장소에 올리지 않는다 |

## 3. 단계별 동작

**1 연결**: 장비 이름, 브로커 호스트·포트, 구독 토픽(여러 개 가능)을 입력해 저장한다. 설정 YAML은 아직 만들지 않는다. 사이클을 세려면 사이클 시작 신호가 있는 토픽(예: `dx1/ProcStart`)도 함께 구독해야 한다.

**2 살펴보기**: "시험 시작"을 누르면 입력한 토픽을 임시로 구독한다. 보여 주는 것: 연결 성공 여부, 초당 수신 건수, 마지막 수신 시각, 마지막 메시지 원문(잘라서), 발견한 숫자 태그 개수와 목록. "시험 종료" 또는 5분 후 자동 종료. 수집 중에는 시험을 켤 수 없다.

**3 전체 수집**: "수집 시작"부터 "수집 종료"까지 구독한 토픽의 payload를 한 줄씩 `capture.jsonl`에 그대로 저장한다. 화면에는 경과 시간, 수신 건수, 파일 크기, 마지막 수신 시각, 감지한 사이클 수(아래 §5)를 보여 준다. 30초 넘게 수신이 없으면 경고한다. "버리고 처음부터"는 현재 수집본을 지운다.

**4 태그 추천**: 수집본에 기존 `deviation_suggest.analyze_tags`를 그대로 돌려 추천 표를 만든다(범위/잡음, 추천·제외 이유). 추천 태그는 미리 체크된다. 이 단계에서 사이클 시작 신호 태그도 고른다(§5).

**5 학습**: "학습 시작" 전에 수집 사이클 수를 확인해 10 미만이면 경고를 보여 준다(그래도 진행 가능). 고른 태그로 설정 YAML을 만들고(`wizard`의 기존 생성·검증 코드), 수집본을 읽어 `replay.train_from_files`로 학습한다. 학습 결과와 신호별 σ·알람 기준 표를 보여 준다.

**6 감시**: 학습이 끝난 모델로 파이프라인을 시작해 감시한다. 지금 감시 화면과 같다. "다시 학습"은 4단계로 돌아간다(같은 수집본 재사용) 또는 3단계에서 새로 수집한다.

## 4. 구조

| 부품 | 변경 |
|---|---|
| `studio/raw_source.py` (새) | 브로커 구독 어댑터(`connect(host, port, topics, on_payload)`, `disconnect`). 테스트에서는 가짜로 바꾼다. 접속 방식은 기존 `mqtt_subscriber`와 맞춘다 |
| `studio/probe.py` (새) | 2단계 시험 세션. 건수·속도·마지막 원문·숫자 태그 집계만 한다. 저장하지 않는다 |
| `studio/collector.py` (새) | 3단계. payload를 `capture.jsonl`에 추가하고 `meta.json`(시작·종료 시각, 건수, 바이트, 토픽)을 갱신한다. 크기 상한. `archive`로 이동, 버리기, 폴더 불러오기(.json/.jsonl 복사) |
| `studio/cycles.py` (새) | 수집본에서 사이클 수와 사이클 시작 신호 후보를 구한다(§5) |
| `studio/wizard.py` | `analyze(수집본 경로)`. 저장 단계 분리: 1단계는 연결 정보만(`studio.json`), 5단계에서 태그를 받아 YAML 생성. `min_samples` 입력 제거 |
| `studio/controller.py` | 단계 상태기계 교체. `COLLECTING`(고른 태그만 모으던 파이프라인)을 없애고 `CONNECT / PROBE / COLLECT / TAGS / TRAIN / MONITOR`로 바꾼다. 학습은 파이프라인 없이 수집본에서 한다. 파이프라인은 6단계에서만 만든다 |
| `studio/server.py` | 라우트 추가(§6). 보안 규칙(토큰, Host/Origin, 본문 한도)은 그대로 |
| `web/studio.html` | 6단계 표시줄과 단계별 화면. 이전 단계로 자유롭게 돌아갈 수 있되 실행 중(수집·학습·감시)에는 막는다 |

기존 `jetson-app`, `jetson-replay` CLI와 `CalibrationManager`는 그대로 둔다. 화면 쪽만 `CalibrationManager`의 수집 기능을 쓰지 않게 된다.

## 5. 사이클 세는 법

수집본의 **사이클 시작 신호**(0/1 태그)가 0에서 1로 바뀌는 횟수를 센다. 신호가 없으면 사이클 수를 알 수 없다.

- 후보: 값이 두 가지뿐인(`binary`) 태그 중 상승 에지가 2번 이상인 것.
- 자동 선택: 후보 중 상승 에지가 가장 적은 것. 같으면 이름순. NX5라면 `U0_ProcStart` 등이 모두 사이클당 한 번이라 같은 수가 나온다.
- 사용자가 4단계에서 다른 후보로 바꿀 수 있다.
- 신호가 없거나 후보가 없으면 "사이클 수를 알 수 없어 수집 시간(분)만 표시합니다"라고 보여 주고, 경고 대신 수집 시간을 안내한다. 이때도 학습은 막지 않는다.
- 3단계 화면의 "감지한 사이클 수"는 수집 중 `cycles.py`를 주기적으로(예: 5초마다) 증분 계산한다.

## 6. API

| 메서드 | 경로 | 동작 |
|---|---|---|
| POST | `/api/connection` | `{equipment_id, host, port, topics}` 저장 |
| POST/GET | `/api/probe/start`, `/api/probe/stop`, `/api/probe` | 시험 시작·종료·조회 |
| POST | `/api/collect/start`, `/api/collect/stop`, `/api/collect/discard` | 수집 시작·종료·버리기 |
| POST | `/api/collect/import` | `{data_dir}` 폴더를 수집본으로 불러오기(복사) |
| GET | `/api/collect` | 수집 상태(경과, 건수, 크기, 사이클 수) |
| POST | `/api/analyze` | 수집본으로 태그 추천 + 사이클 후보 |
| POST | `/api/train` | `{tags, cycle_tag}`로 YAML 생성 후 학습 시작 |
| POST | `/api/start`, `/api/stop` | 감시 시작·중지 |
| GET | `/api/state` | 단계, 오류, 각 단계 요약 |

기존 `/api/config`, `/api/recalibrate`는 새 흐름에 맞게 정리한다. `/api/scores`, `/api/meta`, `/dashboard`는 그대로다.

## 7. 저장 위치

```
workspace/
  studio.json                       # 호스트, 포트, 토픽, 장비 이름
  collections/<equipment_id>/
    current/capture.jsonl           # 원본(한 줄 = payload 하나)
    current/meta.json
    archive/<시각>/...              # 이전 수집본
  configs/<equipment_id>.yaml       # 5단계에서 생성
  models/...                        # 학습 결과
```

모든 쓰기는 `workspace/` 아래로 제한한다. 폴더 불러오기는 지정한 폴더를 읽기만 하고 복사본을 `current/`에 만든다.

## 8. 오류 처리

| 상황 | 동작 |
|---|---|
| 브로커 연결 실패 | 한 줄 안내, 시험·수집은 시작하지 않음 |
| 수집 중 연결 끊김 | 화면에 표시하고 재연결을 시도. 끊긴 동안의 구간은 `meta.json`에 기록 |
| 크기 상한 도달 | 수집 자동 종료, 안내 |
| 추천 태그 없음 | 안내(라인이 멈춘 상태만 모았을 가능성: 축이 움직이는 사이클이 있어야 함) |
| 사이클 10 미만 | 5단계에서 경고만, 학습은 진행 가능 |
| 학습 실패 | 오류 메시지 표시, 수집본은 유지 |
| 앱 재시작 | §2의 복원 규칙 |
| 수집 중 앱 종료 | 파일은 그때까지 쌓인 것을 유지하고, 다음 실행에서 "중단된 수집본"으로 표시 |

## 9. 테스트

- 수집기: 가짜 구독으로 payload가 그대로 저장되는지, 크기 상한, 버리기·archive, 폴더 불러오기.
- 시험: 건수·속도·태그 집계, 저장이 없는지, 수집 중 시작 거부, 5분 자동 종료(가짜 시계).
- 사이클: 합성 신호로 상승 에지 수, 후보 선택, 신호 없음 처리.
- 컨트롤러: 6단계 상태 전이, 복원 규칙, 실행 중 단계 이동 거부, 중복 요청 거부.
- 서버: 새 라우트의 토큰·경로·본문 한도 검사.
- 통합: run3 원본을 가짜 구독으로 흘려 수집 → 추천(X·Z·CV Pos) → 학습(σ 재현) → run4 감시(7/9, 정상 알람 0).
- 화면: 핵심 JS 문자열 검사와 실제 브라우저 확인.
- 기존 489개 중 이 흐름과 무관한 테스트는 그대로 통과해야 한다. 컨트롤러·마법사·서버·화면 테스트는 새 흐름에 맞게 다시 쓴다.

## 10. 이번에 하지 않는 것

- 수집 중 이상 구간을 시간으로 골라 제외하는 기능
- 수집 시간·사이클 수를 채우면 자동 종료하는 모드
- 여러 장비 동시 관리, 인증(브로커 아이디·비밀번호) 입력
- 수집본을 GRU 학습에 쓰는 것

## 11. 알려진 위험

- 사이클 시작 신호가 구독 토픽에 없으면 사이클 수를 못 센다. 1단계 안내에 명시한다.
- 원본 저장이라 용량이 커진다. 초당 수신 건수를 확인해 상한(1GB)이 충분한지 점검해야 한다(run3는 4개 토픽 약 33MB).
- 정지 상태만 모으면 추천이 비어 나온다(범위가 0). 3단계 화면에 "축이 움직이는 사이클이 들어가야 합니다"를 안내한다.
- 라인이 정상이 아닌 구간이 섞이면 기준이 어긋난다. 이를 자동으로 막지 못한다.
- 정상 10사이클은 알람 기준 여유가 얇다. 경고 문구에 명시한다.
