# jetson-studio: 웹 기반 설정·학습·감시 화면 설계

작성일 2026-10-14 / 상태: 검토 대기

## 1. 목적

지금은 설정 YAML 작성, `mosquitto_pub`으로 `train` 명령 전송, 여러 CLI를 순서대로 실행해야 해서 개발자만 쓸 수 있다. 현장 담당자가 **터미널 없이** "설정 → 수집 → 학습 → 감시"를 화면에서 끝낼 수 있게 한다.

성공 기준
- 새 설비 하나를 Claude나 CLI 지식 없이 화면만으로 설정하고, 학습하고, 감시를 시작할 수 있다.
- Windows에서는 exe 더블클릭, Jetson(Linux)에서는 같은 코드를 서비스로 실행하고 PC 브라우저로 접속해 같은 화면을 쓴다.
- 앱과 오프라인 도구가 같은 부품을 쓴다는 원칙을 지킨다. 화면용으로 새로 계산하는 로직을 만들지 않는다.

## 2. 결정 사항 (대화에서 합의됨)

| 항목 | 결정 |
|---|---|
| 사용 환경 | 지금 Windows PC, 최종은 Jetson(Linux) |
| 형태 | 웹 UI를 앱에 내장(A안). Windows는 PyInstaller exe로 포장 |
| v1 범위 | 설정 마법사 + 수집 + 학습 + 감시 |
| 접속 범위 | 기본은 이 장비(127.0.0.1)에서만 조작. 원격은 `--web-host 0.0.0.0` + 토큰이 있을 때만 조작 허용 |
| v1 지원 방식 | `deviation` 전용. GRU는 화면에서 다루지 않음(CLI 유지). exe는 torch 제외 |
| 정상 데이터 입력 | 서버 경로 입력. 파일 업로드는 필요해질 때 추가 |

## 3. 구조

새 진입점 `jetson-studio`를 추가한다. 기존 `jetson-app`, `jetson-replay` 등 CLI는 바꾸지 않는다.

| 부품 | 역할 |
|---|---|
| `studio/controller.py` | 상태(`SETUP`, `COLLECTING`, `TRAINING`, `MONITORING`)를 한곳에서 관리. 파이프라인 생성·시작·중지, 학습을 별도 스레드에서 실행, 이중 요청 거부 |
| `studio/api.py` | 화면이 부르는 JSON API |
| `studio/wizard.py` | 데이터 폴더 → `deviation_suggest.analyze_tags` → 선택 태그로 설정 생성 → `config.load_equipment_config`로 검증 후 저장 |
| `web/studio.html` | 외부 라이브러리 없는 단일 HTML. 기존 점수 그래프 재사용 |
| `studio/cli.py` | `jetson-studio` 진입점. 서버 시작, 브라우저 자동 열기 |

재사용하는 기존 부품: `pipeline.build_pipeline`, `training.make_equipment_train_fn`, `calibration.CalibrationManager`, `deviation_suggest`, `config`, `score_history`, `web_server`(GET 부분).

`web_server.py`는 현재 GET 전용·읽기 전용이다. 조작 API는 별도 핸들러 계층(`studio/api.py`)이 담당하고, 기존 읽기 전용 서버의 동작은 바꾸지 않는다.

## 4. 화면 흐름

상단에 단계 표시줄(1 설정 → 2 수집 → 3 학습 → 4 감시). 현재 상태에 맞는 단계가 자동으로 열린다. 재시작하면 저장된 상태와 모델을 읽어 해당 단계로 열린다.

1. **설정**: 장비 이름, 브로커 주소·포트, 구독/발행 토픽 입력 → 정상 데이터 폴더 경로 입력 → "태그 분석" → 추천 표(범위/잡음, 추천·제외 이유) → 체크박스로 선택 → "설정 저장". 기존 YAML 불러오기 지원.
2. **수집**: 브로커 연결 상태, 받은 스텝 수 / 필요 수(`min_samples`), 진행률, 마지막 수신 시각.
3. **학습**: "학습 시작" 버튼, 진행 표시, 완료 후 신호별 기준값(σ, 움직임 기준, 알람 기준) 표. 기대 범위를 벗어나면 경고.
4. **감시**: 점수 그래프, 알람 표시(어느 신호인지), 알람 이력, "다시 학습".

## 5. API (초안)

| 메서드 | 경로 | 동작 |
|---|---|---|
| GET | `/api/state` | 현재 상태, 진행률, 오류 메시지 |
| GET | `/api/config` | 현재 설정 |
| POST | `/api/analyze` | `{data_dir}` → 태그 추천 결과 |
| POST | `/api/config` | `{...}` → 검증 후 저장 |
| POST | `/api/collect/start` | 수집 시작(브로커 연결) |
| POST | `/api/train` | 학습 시작(스레드) |
| POST | `/api/recalibrate` | 수집부터 다시 |
| POST | `/api/monitor/stop` | 감시 중지 |
| GET | `/api/scores`, `/api/meta` | 기존 그대로 |

## 6. 보안

- 기본 바인딩은 `127.0.0.1`.
- `--web-host`가 루프백이 아니면 `--token`이 필수다. 토큰이 없으면 조작 API(POST)를 등록하지 않고 읽기 전용으로만 연다.
- 모든 POST는 토큰(헤더)과 `Origin`/`Host`를 확인한다. 토큰 비교는 상수 시간 비교를 쓴다.
- 파일 쓰기와 읽기는 작업 폴더(`workspace/`)와 사용자가 분석을 요청한 데이터 폴더(읽기만)로 제한한다. `..` 등으로 벗어나는 경로는 거부한다.
- 요청 본문 크기를 제한한다.

## 7. 오류 처리

화면에는 원인과 할 일을 한 줄로 보여 준다.

| 상황 | 동작 |
|---|---|
| 브로커 연결 실패 | 빨간 표시, "브로커(host:port)에 연결할 수 없습니다. Mosquitto가 실행 중인지 확인하세요" |
| 수집 중 30초 넘게 수신 없음 | "토픽으로 데이터가 오는지 확인하세요" |
| 설정 오류 | 저장 전 `ConfigError` 메시지를 그대로 표시, 파일은 쓰지 않음 |
| 추천 태그 없음 | 기존 안내 문구와 직접 선택 방법 |
| 학습 실패(값이 전혀 안 변함 등) | 기존 `ValueError` 메시지 표시, 상태는 수집 단계 유지 |
| 학습 중 브라우저 닫기·새로고침 | 학습은 서버 스레드에서 계속, 다시 열면 진행 상태 표시 |
| 앱 재시작 | 저장된 상태·모델로 해당 단계에서 재개 |
| 같은 작업 중복 요청 | 상태를 확인해 거부, "이미 학습 중" |

## 8. 테스트

- 컨트롤러: 상태 전이, 중복 요청 거부, 학습 스레드 예외 처리(가짜 학습 함수).
- API: 실제 HTTP로 확인(토큰 없는 POST 거부, 경로 벗어남 거부, 설정 검증 오류 응답, 본문 크기 제한).
- 마법사: 합성 데이터로 태그 추천 → YAML 생성 → `load_equipment_config`가 읽는지.
- 통합: MQTT 없이 스텝을 직접 넣어 수집 → 학습 → 감시를 끝까지. NX5 run3 학습 후 σ가 기존 값(X 3.92e-5, CV 3.44e-5, Z 3.53e-6)과 같고 run4에서 7/9 검출, 정상 알람 0건인지 확인.
- 화면: 핵심 JS 함수(진행률, 상태 문구)를 `tests/test_plot.py` 방식으로 Python과 비교. 실제 브라우저에서 열어 스크린샷으로 확인.
- 기존 430개 테스트는 계속 통과해야 한다.

## 9. 패키징

- Windows: PyInstaller `--onedir`, `jetson-studio.exe`. 더블클릭하면 서버가 뜨고 브라우저가 열린다. 작업 폴더는 exe 옆 `workspace/`(설정, 캘리브레이션 데이터, 모델). `deviation`만 쓰므로 torch를 넣지 않아 크기가 작다.
- Jetson(Linux): exe 없이 `uv run jetson-studio --web-host 0.0.0.0 --token <값>`. systemd 서비스 등록 방법은 README에 문서로만 추가한다.

## 10. 이번에 하지 않는 것

- 재생 검증 화면(`jetson-replay`), 임계값 추천 화면: 기존 CLI 유지
- 여러 설비 동시 관리, 사용자 계정과 권한
- GRU 설정(그룹, `state_tag`) 편집
- 알람 외부 전송(메일, PLC)
- 자동 업데이트, 설치 프로그램(.msi), 파일 업로드

## 11. 알려진 위험

- `deviation` 알람 기준은 정상 10사이클에 근거해 여유가 얇다. 화면에서 기준값을 보여 주되 "충분한 정상 사이클로 다시 학습"을 안내한다.
- 경로 입력 방식은 Jetson을 원격 조작할 때 사용자가 서버 경로를 알아야 해서 불편하다. 사용이 늘면 업로드를 추가한다.
- PyInstaller 빌드는 Windows에서만 검증한다. Linux는 `uv run` 경로만 지원한다.
- 학습 스레드와 파이프라인 스레드가 같은 상태를 건드린다. 컨트롤러가 락 하나로 상태를 보호하고, 기존 `CalibrationManager`의 락 규칙을 따른다.
