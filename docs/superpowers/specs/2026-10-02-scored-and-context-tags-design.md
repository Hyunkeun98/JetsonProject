# 점수 대상 태그와 입력 전용 태그 분리 설계

- 작성일: 2026-10-02
- 상태: 승인 대기
- 선행 스펙: `2026-10-01-process-aware-scoring-design.md` (그룹과 상태별 기준)

## 1. 배경과 목적

NX5 `run1` 데이터(정상 약 66분)로 학습한 GRU를 학습에 쓰지 않은 정상 구간 17분에 적용했더니, 기본 설정(임계값 3, 연속 3스텝)에서 오탐 에피소드가 224건 났다. 알람 상위 태그는 `ProcStart`, `TaktTime`, `ConvSensor` 같은 켜짐/꺼짐·계단형 신호였고, 이진 태그의 알람 에피소드 60%는 그 태그 값이 바뀌는 순간 근처에서 시작했다(무작위 시각은 1%). 바뀌는 순간이 100 ms 단위로 달라지는 것이 오차를 크게 만든 것으로 본다.

사용자의 설비 지식은 다음과 같다.

- 이상 판단은 서보 3축(`AxX`, `AxZ`, `AxCV`)의 Pos/Vel/Trq 9개 값으로 한다.
- `ProcStart`는 어느 공정이 진행 중인지 알려 주는 신호이지 이상 판단 대상이 아니다.
- `AxX`는 `U0_ProcStart`, `AxZ`는 `U4_ProcStart`, `AxCV`는 `U9_ProcStart` 상태로 판별한다.
- 공정이 대기 중일 때의 서보 충격도 잡는다(결정: 대기 중에도 감지).
- `TaktTime`(U0~U10)은 모델 입력으로 넣되 점수에는 반영하지 않는다. 센서 태그는 쓰지 않는다.

**목적:** 설정에서 점수 대상 태그, 상태 신호, 입력 전용 태그를 구분해서, 점수와 알람이 서보 값만으로 계산되게 한다. NX5 전용이 아닌 일반 기능으로 만든다.

## 2. 비목표

- 점수 태그 자동 추천 도구(다음 단계, 별도 스펙).
- TaktTime 값 자체를 정상 범위와 비교하는 검사("공정이 너무 오래 걸림").
- 축마다 별도 모델, 모델 출력에서 입력 전용 태그 제외. 이 방식으로 오탐이 충분히 줄지 확인한 뒤 필요할 때 검토한다.
- `jetson-datalist` 변경. 새 형식은 `nx5` 설정을 직접 쓴다.
- 모델 구조(GRU), 리샘플러, 디바운스, 발행 형식의 변경.

## 3. 설정 형식

```yaml
context_tags:                                  # 선택. 모델 입력으로만 쓰고 점수에는 반영하지 않는다.
  - "NX5_TaktTime:U0_TaktTime"
  - ...
groups:
  axis_x:
    state_tag: "NX5_ProcStart:U0_ProcStart"    # 선택. 동작/대기 상태 신호. tags 밖에 둘 수 있다.
    tags: ["NX5_AxisData:AxX_Act_Pos", "NX5_AxisData:AxX_Act_Vel", "NX5_AxisData:AxX_Act_Trq"]
```

의미:

- 그룹의 `tags`는 **점수 대상**이다. 그룹 점수는 그 태그들의 z 점수 최댓값이다.
- `state_tag`는 상태별 정상 기준을 고르는 조건이다. `tags`에 없으면 **입력 전용**이고 점수에 반영하지 않는다. `tags`에 있으면 지금처럼 점수에도 반영한다(기존 설정과의 호환).
- `context_tags`는 어느 그룹에도 속하지 않는 입력 전용 태그다.
- 모델 입력 태그(`EquipmentConfig.tags`)는 점수 태그, 점수 밖 상태 태그, 입력 전용 태그의 중복 없는 합집합이며, 순서는 점수 태그(그룹 순서), 상태 태그, 입력 전용 태그다.
- MQTT 레코드 필터, 학습, 모델 호환성 검사는 이 모델 입력 태그를 그대로 쓴다.

검증(`ConfigError`):

- `context_tags`는 비어 있지 않은 문자열 리스트이고 `groups`와 함께만 쓸 수 있다(`tags:` 평면 설정과 함께 쓰면 오류).
- 점수 태그는 여러 그룹에 중복될 수 없다(기존 규칙).
- `context_tags`의 태그가 어떤 그룹의 `tags`나 `state_tag`에도 중복될 수 없다.
- `context_tags` 안에서도 중복될 수 없다.
- `state_tag`는 문자열이어야 한다. "tags에 포함돼야 한다"는 기존 규칙은 제거한다.
- 서로 다른 그룹이 같은 `state_tag`를 가리킬 수 있다.

## 4. 점수 계산

- 모델은 모든 입력 태그의 다음 스텝을 예측하고 오차를 계산한다(변경 없음).
- 오차를 정상 기준과 비교한 z 점수는 **그룹의 `tags`에 속한 태그만** 계산한다. 상태별 기준은 그 그룹의 `state_tag` 값(0.5 이상이면 동작 중)에 따라 고르고, 표본이 부족하면 전체 기준으로 대체하는 기존 규칙을 따른다.
- **전체 점수 `anomaly_score`는 그룹 점수의 최댓값**이고 `top_deviant_tag`는 그 최댓값을 낸 그룹의 원인 태그다. 지금은 모든 태그의 최댓값이라, 점수 대상이 아닌 태그가 전체 점수를 올릴 수 있다.
- 알람(그룹별 디바운스, 전체 알람은 그룹 알람의 OR)과 발행 필드 형식은 그대로다.
- 점수 대상이 없는 태그(입력 전용)는 `top_deviant_tag`가 되지 않는다.

## 5. 변경 범위

| 파일 | 변경 |
|---|---|
| `config.py` | `context_tags` 파싱과 검증, `state_tag`가 `tags` 밖일 수 있게 완화, `EquipmentConfig.tags`를 모델 입력 태그(합집합)로, `context_tags` 필드 추가 |
| `inference.py` | z 점수를 그룹 태그에 대해서만 계산, 전체 점수와 `top_deviant_tag`를 그룹 점수의 최댓값으로 |
| `training.py`, `pipeline.py`, `subscriber_cli.py`, `publisher.py`, `snapshot_processor.py` | 변경 없음(모델 입력 태그를 `config.tags`로 이미 받는다). 필요하면 회귀 테스트만 추가 |
| `configs/nx5_servo.yaml` (새 파일) | 서보 3축 그룹, `ProcStart` 3개, `TaktTime` 11개를 입력 전용으로. 구독 토픽은 `AxisData`, `ProcStart`, `TaktTime` |
| `README.md` | 점수 태그/입력 전용 태그 설명, `nx5_servo.yaml` 예 |

저장된 모델은 `tags`(모델 입력 태그)나 `groups`가 달라지면 기존 규칙대로 `CALIBRATING`으로 되돌아가므로 재학습한다.

## 6. 테스트

단위 테스트(`pytest`):

1. `context_tags`가 모델 입력 태그에 포함되고 점수 태그에는 포함되지 않는다.
2. `state_tag`가 `tags` 밖이어도 로드된다. 모델 입력 태그에는 들어가고, 그룹의 점수 태그에는 들어가지 않는다.
3. 검증 오류: 중복(`context_tags` 안, 그룹 태그와 중복), 빈 리스트, 평면 `tags`와 함께 사용.
4. 추론: 입력 전용 태그와 점수 밖 상태 태그의 오차가 크게 나와도 전체 점수와 그룹 점수에 영향을 주지 않는다. 전체 점수는 그룹 점수의 최댓값이다.
5. 호환: 기존 형식(`state_tag`가 `tags`에 포함, 평면 `tags`)의 점수가 변경 전과 같다(기존 테스트 통과).
6. 모델 호환성: `context_tags`를 바꾸면 저장된 모델이 호환되지 않는다고 판정된다.

데이터 검증(`run1`, 로컬 비공개 포트 브로커):

- **비교 실험:** 앞 두 구간(11:15~11:32:50, 11:37:05~11:53:05, 약 19,350스텝)으로 학습하고 마지막 구간(12:11~12:28)에서 오탐을 센다. 이전 모델의 같은 조건 결과(임계값 3, 연속 3스텝에서 224건, 서보 그룹 96건)와 비교한다. 학습 제외는 사용자가 Error로 표시한 두 구간(11:32:57~11:36:59, 11:53:11~11:56:16, 몇 초 여유)만이다.
- **최종 학습:** Error 구간을 뺀 전체 정상 데이터(약 39,000스텝)로 학습하고 학습 시간을 잰다.
- **선택 비교:** `TaktTime`을 뺀 입력으로 같은 실험을 해서 `TaktTime`의 영향을 본다.

## 7. 완료 기준

- 전체 테스트 통과(기존 253개 + 신규).
- `nx5_servo.yaml`로 학습한 모델에서 `ProcStart`와 `TaktTime`이 `top_tag`가 되지 않는다.
- 비교 실험에서 오탐 에피소드 수를 이전 모델(224건)과 나란히 보고한다. 임계값은 이번 변경에서 확정하지 않는다(이상 데이터 `run2`로 민감도를 확인한 뒤 정한다).

## 8. 위험과 열린 문제

- 서보 태그만으로도 오탐이 남을 수 있다(`AxZ_Act_Vel` 등 연속 태그의 원인은 아직 모른다). 남으면 오차 기준 하한(`_floor_std`), 윈도우 크기, 학습량을 따로 검토한다.
- `TaktTime` 입력이 모델을 불안정하게 만들 수 있다. 선택 비교로 확인한다.
- 정상 데이터에는 서보가 대기 중일 때 움직이는 구간이 섞여 있을 수 있다(예: `AxCV`). 대기 기준이 넓어져 대기 중 충격을 놓칠 수 있으니 결과를 보고 확인한다.
- 임계값 조정과 이상 데이터를 통한 민감도 검증은 이번 범위 밖이다.
